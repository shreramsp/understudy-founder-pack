# D04 · Three-layer library schema

```mermaid
erDiagram
  ENVIRONMENT_LAYER {
    string tenant_id "client identity — NEVER crosses"
    string policy_ids "configuration values"
    json   drift_history
    json   endorsements "which engineer signed off"
  }
  MSP_LAYER {
    string msp_id
    json   procedure_clusters "across this MSP's 41 environments"
    json   variance_distribution "how tenants differ"
    int    observation_counts
  }
  GLOBAL_LAYER {
    string procedure_shape "closed vocabulary"
    string precondition_pattern
    string deviation_class
    int    tenant_observation_count "k>=3 to be eligible"
  }
  ENVIRONMENT_LAYER ||--o{ MSP_LAYER : "clusters into (stays in MSP tenant)"
  MSP_LAYER ||--o{ GLOBAL_LAYER : "abstracts into (whitelist + k-anonymity)"
```

**What a reviewer should notice.** The middle layer is the one the first design omitted, and it is where the customer's own compounding happens — an MSP's 41 environments clustering together, inside its own tenant, crossing no new trust boundary because it already administers all of them. The global layer's fields are a **closed vocabulary**: it cannot express a tenant name because there is no field for one (DD4's whitelist construction). The `k>=3` threshold is the actual guarantee — a deviation seen in one tenant is a fingerprint, and does not cross.
